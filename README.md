# 🧠 Mind Reader

Think of a whole number in 1–50, 1–100, 1–250 or 1–1000 and keep it secret. The computer finds it by asking
mathematical yes/no questions (parity, primes, squares and cubes, divisibility, remainders, digit properties).
It never asks "Is it N?" and never "higher or lower". Runs fully offline, no dependencies, no network.

## Play

Open `index.html` in any modern browser (double-click it). Keep the `css/` and `js/` folders next to it.
If you want a single file, open **`mind_reader_standalone.html`** instead (same game, everything inlined).

- **Yes / No** narrow the possibilities. **Not sure** narrows nothing and is marked ❓ Uncertain.
- Wrong answer? Use the Yes / No / Not sure buttons on any earlier row, or **Undo**. Counts are recalculated.
- When exactly one number fits, the computer names it and asks you to confirm. A mistaken "not my number" click can be
  undone or restored.
- Keyboard: **Y** / **N** / **S** answer; Tab / Enter / Space work everywhere.
- **Division Calculator** (side panel): type a dividend and divisor and see the quotient and remainder instantly
  (58 ÷ 7 → 8 remainder 2). It is a convenience for checking remainders; it only uses the numbers typed into it and
  knows nothing about the game.

## Layout

| File | Responsibility |
|---|---|
| `js/questions.js` | **Question generation.** Question bank, structural legitimacy guards, adaptive generator |
| `js/engine.js` | **Candidate filtering** and **question selection** (pure functions) |
| `js/game.js` | **Game state** machine: answers, rejections, undo, corrections, repair suggestions |
| `js/ui.js` | **UI** only: renders the game view, no rules |
| `js/calculator.js` | **Division Calculator** logic (pure, BigInt, independent of the game) |
| `js/calculator-ui.js` | Division Calculator panel wiring (touches only `#calcPanel`) |
| `css/style.css`, `index.html` | Presentation |
| `tools/build-standalone.js` | Builds `mind_reader_standalone.html` |
| `tests/` | Test suites and their generated result reports |
| `AUDIT.md`, `CHANGELOG.md` | What was wrong, what changed |

## How it avoids direct questions

A question is accepted only if, over the whole range, both its yes-set and no-set have at least 3 numbers and at
least 3 separate stretches of consecutive integers. A single number, a pair, or a cutoff such as "at least 100" or
"exactly two digits" therefore cannot pass, whether it comes from the standard bank or the adaptive generator.
Question text is also checked for ordering words.

## Limitations (please read)

- **Browsers tested:** Chromium only (headless, Linux). Firefox, Safari and real phones/tablets were **not** tested;
  small-screen results come from viewport emulation at 320, 375, 768 and 1280 px.
- **Screen readers were not tested.** ARIA attributes, an aria-live region and focus handling are in place and checked
  programmatically, but real assistive-technology behaviour is unverified.
- **Contrast** was computed from the palette's text/background pairs (all ≥ 4.5:1, minimum 7.83:1), not measured from
  rendered pixels.
- The in-browser exhaustive test decides truthful answers using the page's own question definitions. Independent
  re-implementations of the named questions and all residue questions are cross-checked separately in the Node suite.
- "Varied" order uses `Math.random` in the real page. Tests exercise it with seeded generators and fuzzing, not an
  exhaustive replay of every possible random draw; correctness does not depend on the draw, only on the splits.
- The final reveal asks the player to confirm ("Is N your number?"). That is a confirmation after deduction, not a
  question used to find the number; it is the only place a specific number is shown.
- Selection is greedy (most even split now), not provably optimal. Some questions (primes, cubes) take effort for
  4-digit numbers; Not sure is the safe answer, but answering Not sure too often can make a round long or end in the
  "stuck" screen, which refuses to guess.
- Re-asking Not sure questions removes those answers, so the Q numbers of later rows shift.
- "Extra" generated questions are exercised heavily in tests but are rarely needed in normal play, since the standard
  bank always suffices for truthful answers.
- **Division Calculator notes:**
  - Negative values use Euclidean division so the remainder is never negative, also for a negative divisor
    (58 ÷ -7 → -8 r 2). Other conventions (truncating division) give different quotients for negative inputs.
  - The fields are text fields with a numeric-keypad hint so that invalid text can be detected and explained. On some
    phone keypads there may be no minus-sign key; this was **not** tested on real devices.
  - It needs `BigInt`, available in all current browsers (not in very old ones).
  - Between 1060 and 1359 px wide the game card sits 135 px left of centre to make room for the panel; on wider
    screens it stays centred, below 1060 px the panel stacks under the game.
- No claim of perfection is made: these tests show the listed behaviours on the listed inputs.
